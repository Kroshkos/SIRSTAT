# SIRSTAT — анализ антибиотикорезистентности и эпидемиологии посевов

**SIRSTAT** — десктопная программа для микробиологических лабораторий: обрабатывает
результаты бактериальных посевов и антибиотикограмм и формирует готовый
**Excel-отчёт** из исходного файла LIS/HIS-выгрузки. Внутри — базовые листы
статистики, пользовательские листы конструктора и режим **сравнения клиник**
с диаграммами.

Работает на **Windows**, **macOS** и **Linux**. Готовые сборки публикуются в
Releases (GitHub Actions собирает их автоматически при выпуске тега `v*`).

## Возможности

- **Современный интерфейс** на CustomTkinter: тёмная/светлая тема, карточки,
  прогресс-бар, журнал обработки с цветными метками, строка состояния.
  Обработка идёт в фоновом потоке — окно не «замерзает».
- **Автоопределение структуры файла.** Программа сама находит лист с данными,
  строку заголовков и блок антибиотиков; жёстких требований к оформлению нет.
- **Автоопределение клиник** (столбец «Клиника» или первый столбец-разделитель,
  например ВМХ / ВПХ / ГХ) с числом посевов каждой.
- **Три режима работы**:
  - конкретная клиника — отчёт только по её данным;
  - **«Все клиники»** — каждая клиника обрабатывается отдельно, сохраняется
    по файлу на каждую (`отчёт — ВМХ.xlsx`, `отчёт — ВПХ.xlsx`, …);
  - **«⚖️ Сравнение клиник»** — сравнительные таблицы и диаграммы чувствительности
    по отмеченным клиникам (базовые листы при этом не создаются).
- **Конструктор листов** — неограниченное число дополнительных листов отчёта:
  группировка по любому сочетанию полей (микроорганизм, материал, категория,
  год/месяц/неделя/квартал, пациент…), набор метрик, антибиотикограмма по выбранному
  антибиотику или суммарная, фильтры, готовые шаблоны, сохранение/загрузка
  пресетов в JSON. Внутри конструктора тоже доступен режим «⚖️ Сравнение клиник».
- **Диаграммы сравнения** — столбчатые графики S% по микроорганизмам для каждой
  клиники; данные фильтруются («только то, для чего есть значения»), таблица и
  графики лежат на отдельных листах.
- **Порог значимости n ≥ S+I+R** — единое поле на главном окне: строки/ячейки с
  числом определённых ответов ниже порога не попадают в листы (0 = без порога).
- **Красивое оформление Excel** (переключается): стилизованные шапки, «зебра»,
  рамки, автоширина, условная подсветка процентов (S% ≥ 80 — зелёный, < 50 — красный),
  листы «Сводка» и «Данные», заморозка заголовков.
- **Автоматическая сборка и публикация релизов** через GitHub Actions
  (Windows + macOS), с поддержкой кодовой подписи и нотаризации (см. `SIGNING.md`).

1. Откройте страницу **Releases** этого репозитория.
2. Скачайте архив под вашу систему:
   - **Windows** → `SIRSTAT-windows.zip`
   - **macOS** → `SIRSTAT-macos.zip`
3. Распакуйте архив в любую папку (например `C:\SIRSTAT\`).

   «Открыть» → «Открыть»**, либо выполните в Терминале:

   ```bash
   xattr -dr com.apple.quarantine /Applications/SIRSTAT.app
   ```

4. Готово — откроется главное окно SIRSTAT.

> Не запускайте `.exe` «напрямую» из архива — сначала распакуйте всю папку:
> программе нужны файлы-зависимости рядом с исполняемым файлом.

## Формат входных данных

Поддерживаются `.xlsx`, `.xlsm` и старые бинарные `.xls` (движок `xlrd` встроен в сборку).

Типичная выгрузка лаборатории (пример — `данные.xls` в репозитории):

| Колонка | Обязательна | Примечание |
|---|---|---|
| Клиника | нет | либо первый столбец-разделитель с короткими кодами (ВМХ/ВПХ/ГХ…) |
| Заказ / № истории | нет | используется как идентификатор пациента |
| Дата | нет | даёт группировки по году/месяцу/неделе/кварталу |
| Материал | нет | «мазок с раны», «моча» и т. п.; автоматическая категория (рана/моча/кровь/…) |
| Микроорганизм | да | видовой состав посевов |
| Блок антибиотиков | да | две колонки на антибиотик: MIC и RSI (S/I/R/НД); значения берутся из правых колонок пар |

Жёсткие требования к оформлению сняты:

- лист с данными находится автоматически (предпочитается `TDSheet`, иначе —
  первый подходящий);
- строка заголовков ищет ключевые слова («Заказ», «Дата», «Материал»,
  «Микроорганизм» и аналоги);
- строка с названиями антибиотиков определяется по блоку парных колонок;
- дублирующиеся заголовки колонок RSI/MIC не проблема — обращение позиционное;
- колонки «Дата» и «Материал» необязательны (соответствующие группировки просто
  станут недоступны).

Если столбец клиники не найден, весь файл трактуется как единая выборка
(«Общая выборка»).

## Полная инструкция пользователя

Интерфейс главного окна сверху вниз: шапка с переключателем темы → карточка файлов →
карточка режима «Клиника» (и панель сравнения) → панель действий (конструктор,
порог значимости, оформление, запуск) → прогресс-бар → журнал → строка состояния.

### Шаг 1. Загрузите исходный файл

1. Нажмите **«Обзор…»** в карточке «Исходный файл» и выберите файл посевов
   (`.xls`, `.xlsx`, `.xlsm`).
2. Программа в фоне прочитает файл и определит:
   - список **клиник** (например: ВМХ, ВПХ, ГХ — с числом посевов у каждой);
   - список **антибиотиков**.
3. Клиники появятся в меню «Клиника:», антибиотики — в панели сравнения (если
   выбран режим сравнения) и в конструкторе листов; ход сканирования виден в журнале.
4. Имя результирующего файла подставляется автоматически
   (`<имя>_обработанный_ГГГГММДД_ЧЧММ.xlsx` в той же папке) — его можно изменить
   кнопкой **«Сохранить как…»**.

### Шаг 2. Выберите режим обработки (меню «Клиника»)

| Выбор | Что произойдёт |
|---|---|
| Конкретная клиника (напр. **ВМХ**) | Весь отчёт строится только по данным этой клиники |
| **Все клиники** (по умолчанию) | Каждая клиника обрабатывается отдельно; сохраняется **по файлу на клинику** (`… — ВМХ.xlsx`, `… — ВПХ.xlsx`, `… — ГХ.xlsx`) |
| **⚖️ Сравнение клиник** | Отдельный режим: сравнительные листы по отмеченным клиникам; базовые листы не создаются (см. шаг 4) |

Если в файле одна клиника (или столбца «Клиника» нет), выбор клиники недоступен —
данные обрабатываются как единая выборка.

### Шаг 3. Соберите листы в конструкторе

Кнопка **«🧩 Конструктор листов…»** открывает модальное окно со списком карточек
дополнительных листов. Листы конструктора добавляются в отчёт **после трёх базовых**
листов.

Для каждой карточки настраивается:

1. **Режим листа** — «Обычный лист (группировка и метрики)» или
   «⚖️ Сравнение клиник (АБГ по разным клиникам)».
2. **Название** — имя листа в Excel (ограничение Excel — 31 символ, длинные имена
   сокращаются автоматически; дубликаты имён запрещены — программа предупредит).
3. **Группировать по** — любое сочетание полей: микроорганизм, материал, категория
   материала, клиника, год, месяц, неделя, квартал, пациент…; эксклюзивный режим
   «Всё вместе» строит одну итоговую строку по всей выборке. Под чекбоксами
   показывается итоговая схема группировки.
4. **Метрики** — всего проб, посевов с ростом, % положительных, диагностичных,
   уникальные пациенты + **антибиотикограмма (S/I/R/НД)**. Для антибиотикограммы
   выберите конкретный антибиотик или «⭐ Все антибиотики» (суммарная АБГ).
5. **Фильтр** — только с ростом, только раны, только моча, кровь и катетеры и т. д.
6. **Шаблон →** — типовые сценарии одним выбором (динамика резистентности по
   месяцам, АБГ по микроорганизмам и т. п.); применяется к последней карточке.

Сервисные кнопки окна конструктора:

- **«💾 Сохранить пресет…»** / **«📂 Загрузить пресет…»** — набор листов хранится
  в JSON и многократно переиспользуется (в т. ч. на других файлах);
- **«🔄 Обновить список антибиотиков»** — перечитать антибиотики и клиники из
  исходного файла главного окна (актуально, если файл был выбран позже открытия
  конструктора);
- **«✕»** на карточке — удалить лист; **«＋ Добавить лист»** — создать новый;
- **«✔ Применить»** — проверить настройки (валидация полей, дубликатов, доступности
  антибиотиков) и закрыть окно; **«Отмена»** — закрыть без применения.

> Совет: режим «⚖️ Сравнение клиник» доступен и как отдельный лист *внутри*
> обычного отчёта — отметьте в карточке клиники и антибиотики. Такой лист строится
> по полному файлу независимо от выбранной клиники.

### Шаг 4. Режим «Сравнение клиник»

1. В меню «Клиника» выберите **«⚖️ Сравнение клиник»** — под ним раскрыется панель
   сравнения, а кнопка конструктора блокируется (базовые листы в этом режиме
   не создаются).
2. Настройте сравнение:
   - **Список антибиотиков** — мультивыбор с Ctrl/Shift, поиск по названию,
     кнопки «Выбрать все» / «Снять всё». **Ничего не отмечено = сравниваются все
     антибиотики файла**;
   - **Чекбоксы клиник** («Клиники для сравнения, отметьте минимум две») —
     заполняются из исходного файла после его выбора;
   - **«💾 Сохранить настройки сравнения…»** / **«📂 Загрузить настройки
     сравнения…»** — JSON-пресет (клиники, антибиотики, фильтр);
   - служебная строка внизу всегда показывает, что именно будет сравниваться
     (число выбранных антибиотиков и клиники; предупреждение ⚠️, если клиник < 2).
3. Укажите результирующий файл и нажмите **«▶ Запустить обработку»**.
4. Результат — один Excel-файл с листами:
   - **таблица сравнения** (структура как у листа 3: блоки «Антибиотик…»,
     подблоки «Клиника…», строки «микроорганизм × локализация», показатели
     S/I/R/НД/Total/S%/I%/R%/НД%, строки «ВСЕГО» по клинике);
   - **«… (данные)»** — компактные блоки данных, на которые ссылается лист
     диаграмм (S% по каждому антибиотику);
   - **«… (графики)»** — **только столбчатые диаграммы S% по микроорганизмам**
     (без таблиц): клиники-серии, легенда справа за областью графика, ось значений
     слева, метки данных на столбцах отсутствуют. На график попадает только то,
     для чего есть данные: микроорганизм отображается, если значение S% есть
     минимум у двух клиник; клиники без данных исключаются.

### Шаг 5. Порог значимости и оформление

- **«Порог значимости n ≥»** (главное окно) — минимальное число **определённых**
  ответов (S+I+R) для попадания строки/ячейки в листы. Действует во всех режимах
  одинаково: базовые листы, листы конструктора, сравнение клиник и диаграммы.
  `0` = без порога. Пример: при `n ≥ 10` процент чувствительности по антибиотику,
  где суммарно 7 посевов с ответом, не рассчитывается и не рисуется.
- **«Красивое оформление Excel»** — включает стилизацию (шапки, «зебра», рамки,
  подсветка S% ≥ 80 зелёным и < 50 красным, автоширина колонок, заморозка
  заголовков). Выключите, если нужен «сырой» экспорт для дальнейшей обработки
  формулами.

### Шаг 6. Запуск обработки и результат

1. Нажмите **«▶ Запустить обработку»**. Кнопка блокируется до завершения,
   прогресс-бар анимируется, журнал пишет ход работы:
   `[время] ✅ …` — успех, `[время] ⛔ ОШИБКА: …` — сбой (плюс всплывающее окно).
2. Ход обработки: чтение файла → определение структуры и клиник → расчёт базовых
   листов → листы конструктора → сохранение с форматированием.
3. По завершении: проверьте журнал, нажмите **«Открыть папку результата»** —
   откроется проводник с итоговым файлом (для режима «Все клиники» — папка с
   наборами файлов по клиникам).
4. Если в журнале ошибка — скопируйте её текст (он содержит этап и причину)
   и приложите к сообщению об ошибке в Issues.

## Что внутри отчёта (структура листов)

### Обычный отчёт (режимы «конкретная клиника» / «Все клиники»)

| # | Лист | Содержание |
|---|---|---|
| 1 | Анализ посевов | структура посева: всего, с ростом, % положительных, по категориям материалов |
| 2 | Эпидемиология | частота микроорганизмов по локализациям/материалам |
| 3 | Антибиотикорезистентность | АБГ: блоки по антибиотикам × микроорганизмы, S/I/R/НД и проценты |
| + | Сводка | ключевые показатели одной страницей (открывается активной) |
| + | Данные | очищенные исходные строки с категорией материала |
| + | … | листы конструктора (любое число, после базовых) |

### Режим «Сравнение клиник»

| Лист | Содержание |
|---|---|
| Сравнение клиник | сводная сравнительная таблица |
| Сравнение клиник (матрица) / (матрица-микробы) | матрицы S% «антибиотик × клиника» и «микроб × клиника» |
| Сравнение клиник (данные) | компактные блоки данных для диаграмм |
| Сравнение клиник (графики) | только диаграммы S% по микроорганизмам |

## Методика расчётов

- **Ответы RSI**: `S` — чувствителен, `I` — промежуточный, `R` — резистентен,
  `НД` — не определено/нет роста и т. п. Определяются только S/I/R.
- **S%** (чувствительность) = (S + I) / (S + I + R) × 100 — доля штаммов,
  на которые антибиотик действует (промежуточные считаются эффективными,
  согласно CLSI/EUCAST-практике эпидемиологического мониторинга).
- **Значимость**: ячейка/строка участвует в расчёте и диаграммах, только если
  общее число определённых ответов n = S+I+R ≥ порога (поле «Порог значимости»;
  0 — порог не применяется).
- **Диаграммы сравнения**: категории — микроорганизмы (без разбивки по
  локализации; значения усредняются по всем материалам микроба в клинике);
  серии — клиники; в график включаются только микробы с данными минимум у двух
  клиник и клиники с хотя бы одним значением. Пустые значения отображаются
  разрывом, а не нулём.
- **Категории материалов** определяются по ключевым словам (рана, моча, кровь,
  мокрота, мазок из зева, катетер и т. д.) и используются фильтрами и
  группировками.

## Использование без GUI (API ядра)

Вся логика находится в `app_core.py` и вызывается программно:

```python
from app_core import (
    load_data, detect_clinics, get_file_info, run_pipeline,
    run_pipeline_multi_clinic, run_clinic_comparison,
)

# одна клиника / общая выборка
run_pipeline('данные.xls', 'otchet.xlsx', styled=True, log_func=print,
             clinic='ВМХ')

# все клиники -> отдельный файл на каждую
files = run_pipeline_multi_clinic('данные.xls', 'otchet.xlsx',
                                  styled=True, log_func=print)
# {'ВМХ': 'otchet — ВМХ.xlsx', 'ВПХ': ..., 'ГХ': ...}

# сравнение клиник
spec = {'name': 'Сравнение клиник', 'mode': '__compare_clinics__',
        'clinics': ['ВМХ', 'ВПХ'],          # пусто/нет ключа — все клиники
        'antibiotics': [],                  # пусто — все антибиотики
        'compare_by': ['organism', 'material_raw'],
        'filter': 'positive_only',
        'min_n': 10}                        # порог значимости (0 — без порога)
run_clinic_comparison('данные.xls', 'compare.xlsx', spec,
                      styled=True, log_func=print)

# что умеет файл
clinics, antibiotics = get_file_info('данные.xls')
```

Дополнительно: `build_sheet_from_spec(spec, ...)` — сборка одного листа
конструктора; `validate_spec(spec, available_antibiotics)` — валидация;
`save_sheet_specs` / `load_sheet_specs` — JSON-пресеты обычных листов;
`save_compare_preset` / `load_compare_preset` — пресет сравнения.

## Сборка исполняемого файла из исходников

Локальная сборка (тот же `build.spec`, что использует CI):

```bash
pip install -r requirements.txt pyinstaller
pyinstaller build.spec --noconfirm
# Windows: dist\SIRSTAT\SIRSTAT.exe
# macOS:   dist/SIRSTAT.app
```

Сборка **one-dir** (папка с exe + зависимостями) — сознательный выбор:
запускается заметно быстрее однофайловой и реже провоцирует антивирусы.
В `build.spec` подключены ассеты `customtkinter` (без них UI не стартует) и
`xlrd` (чтение старых `.xls`); неиспользуемые тяжёлые модули исключены.

## Релизы и CI/CD

- `.github/workflows/build.yml`: при пуше тега `v*` (или ручном запуске)
  собирает приложение на `windows-latest` и `macos-latest`, упаковывает в
  `SIRSTAT-windows.zip` / `SIRSTAT-macos.zip` и публикует **GitHub Release**
  с этими артефактами.
- Как выпустить версию — см. [`RELEASE.md`](RELEASE.md).
- Кодовая подпись Windows и нотаризация macOS настраиваются секретами
  репозитория — пошагово в [`SIGNING.md`](SIGNING.md). Пока секреты не заданы,
  сборки публикуются неподписанными (первый запуск на macOS требует
  «Открыть» по правому клику, SmartScreen на Windows может предупреждать).

## Частые вопросы (FAQ)

**Клиники не определились.**
Проверьте наличие столбца «Клиника» (или первого столбца с короткими
повторяющимися кодами). Файл из одного раздела обрабатывается как единая
выборка («Общая выборка»).

**Ошибка «отметьте минимум две клиники».**
В режиме сравнения нужно минимум две разные клиники в файле и минимум две
отмеченные чекбоксами.

**Программа долго запускается в первый раз.**
Это нормально для PyInstaller-сборок (распаковка runtime); повторные запуски
быстрые. One-dir-сборка специально выбрана ради скорости старта.

**Антивирус блокирует SIRSTAT.exe.**
Неподписанные сборки иногда получают ложные срабатывания. Решения: добавить
папку в исключения; дождаться подписанного релиза (настройка — `SIGNING.md`);
либо запускать из исходников (`python 1.py`).

**Старый `.xls` не открывается.**
Убедитесь, что это настоящий бинарный `.xls` (не переименованный `.xlsx`).
Движок `xlrd` встроен в сборку; для исходников — `pip install xlrd`.

**Листы с русскими именами обрезаются.**
Имена листов Excel ограничены 31 символом — длинные имена сокращаются
автоматически, это ограничение формата, а не программы.

**Диаграммы пустые / мало столбцов.**
Так работает правило «только существующие данные»: микроб попадает на график,
только если S% есть минимум у двух клиник; при высоком пороге значимости часть
строк отсекается. Понизьте порог — и проверьте лист «… (данные)», откуда
берутся значения.

**Как сравнить два периода?**
Выгрузите оба периода в один файл с колонкой, различающей периоды, добавьте её
как поле группировки в конструкторе (год/месяц/неделя/квартал) или используйте
фильтры пресетов.
